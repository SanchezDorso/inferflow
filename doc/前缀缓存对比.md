# 前缀缓存：vLLM 和 InferFlow 命中一样多，批量时才明显变快

Qwen3-0.6B，RTX 4090 D。共享前缀 2048 token，每条再加 32 个不同的后缀，只生成 1 个 token。两边块大小都是 16。vLLM 0.15.0。数字是各自热身之后的第二次测量。来源：本机实测，2026-10-27。

| 指标 | 数值 |
| --- | --- |
| 单条再次请求的命中，两边相同 | 2048 / 2080 |
| vLLM 八条一起，开缓存相对关缓存 | 2.9× |
| InferFlow 八条一起，开缓存相对关缓存 | 2.5× |
| 两边的块大小 | 16 token |

## 八条共享前缀一起提交

整批完成时间（秒）。前缀已经由前面的单条请求写进缓存。

| | 前缀缓存开 | 前缀缓存关 |
| --- | ---: | ---: |
| InferFlow | 0.073 s | 0.180 s |
| vLLM | 0.069 s | 0.202 s |

## 同一条前缀的第二次单请求

单条请求的完成时间（秒）。缓存开着时，2048 个前缀 token 全部命中，只重算 32 个后缀。

| | 前缀缓存开 | 前缀缓存关 |
| --- | ---: | ---: |
| InferFlow | 0.059 s | 0.051 s |
| vLLM | 0.029 s | 0.031 s |

第二次单请求两边都是 2048/2080 命中。vLLM 从 0.031 秒降到 0.029 秒。InferFlow 从 0.051 秒变成 0.059 秒，命中之后反而略慢。0.6B 上，重算 2080 个 token 的整段 prefill 已经很短，分页去读 2048 长的缓存并没有更便宜。八条一起时，前缀只算一次，两边都从大约 0.18–0.20 秒降到 0.07 秒。

## 命中 token

关缓存时 vLLM 不再统计 query。2048 能被 16 整除，所以整段前缀都能命中，剩下的是每条自己的 32 token 后缀。

| 场景 | InferFlow 开 | InferFlow 关 | vLLM 开 | vLLM 关 |
| --- | ---: | ---: | ---: | ---: |
| 第一次单请求 | 0 / 2080 | 0 / 2080 | 0 / 2080 | 0 |
| 第二次单请求 | 2048 / 2080 | 0 / 2080 | 2048 / 2080 | 0 |
| 八条一批 | 16432 / 16640 | 0 / 16640 | 16432 / 16640 | 0 |
