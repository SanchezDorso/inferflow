# 温度采样：不再写出整张概率

机器：RTX 4090 D。词表 151936。temperature=0.6 时，旧实现先把 logits 升成 fp32，再 softmax，再做 Gumbel-max：`argmax(p / E)`，E ~ Exp(1)。一批 256 条序列，这张 fp32 概率是 148.4 MiB。

新实现是一个 Triton kernel，按行扫描 `argmax(logit / T - log E)`，E 在寄存器里从均匀随机数现算，不写出概率，也不写出整表噪声。temperature=0 的行仍然直接用 logit 做 argmax。整批温度都是 0 时不进这个 kernel。`INFERFLOW_FUSED_SAMPLE=0` 走原来的 softmax 路径。

和旧公式等价：`argmax(softmax(z) / E) = argmax(z - log E)`，z = logit / T。词表前 4 项 logit 为 2、1、0、-1、其余为 0、T=0.8 时，2000 次采样的频率排序两边都是第 0 项最高、然后第 1、2、3 项。logit 比其余高 13、T=0.6 时，200 次都采到峰值。混合批里温度为 0 的那一行和 `argmax` 一致。

## 采样算子

logits 为 bfloat16，形状 `[B, 151936]`，温度全是 0.6。热身 10 次后测 30 次，用 CUDA event 计时。峰值是调用期间相对 logits 本身多出来的显存。

| 批大小 | 概率张量 | 融合前 | 融合前多占显存 | 融合后 | 融合后多占显存 | 加速 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 0.6 MiB | 0.239 ms | 1.2 MiB | 0.282 ms | 0.0 MiB | 0.85× |
| 32 | 18.5 MiB | 0.256 ms | 72.0 MiB | 0.199 ms | 0.0 MiB | 1.29× |
| 256 | 148.4 MiB | 0.508 ms | 148.4 MiB | 0.313 ms | 0.002 MiB | 1.62× |

一批 256 条时，旧路径峰值多出 148.4 MiB，就是那张 fp32 概率。新路径多出 2 KiB，只是 256 个 token id。单条序列时 kernel 启动盖过了省下的带宽，所以略慢。

## 端到端

同一进程里先关融合、再开融合。256 条请求，prompt 16，生成 32 token，temperature=0.6，ignore_eos。每组先热身一次，再跑 5 次，取中位数。输出共 8192 token。max_num_seqs=256，所以每个解码步都按 256 条采样。

| | 中位数 | 输出吞吐 | 5 次（ms） |
| --- | ---: | ---: | --- |
| 融合前 | 389.81 ms | 21015 tok/s | 385.59, 389.33, 389.81, 394.96, 410.90 |
| 融合后 | 373.35 ms | 21942 tok/s | 371.54, 371.91, 373.35, 374.22, 374.93 |

少 16.46 ms，约 4.2%。输出吞吐从 21015 tok/s 到 21942 tok/s。解码步里还有 matmul 和注意力，采样只是其中一段。
